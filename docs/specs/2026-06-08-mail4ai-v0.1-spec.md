# Mail4AI Public Agent Kit v0.1 Spec

## 1. Purpose

Version 0.1 establishes the first useful public slice of the Mail4AI agent
integration kit.

The release must make the repository understandable without access to the
private AgentMail platform repository. It must document the canonical webhook
contract and provide a small TypeScript helper package that agent runtimes and
examples can use to verify Mail4AI webhook notifications safely.

## 2. Scope

v0.1 includes:

- public repository bootstrap documentation;
- canonical `agentmail_hmac_v1` webhook protocol documentation;
- public Mail4AI security model documentation;
- MCP usage guidance for agents after webhook wake-up;
- `@mail4ai/webhook-kit` TypeScript package;
- unit tests for signature verification, freshness, payload validation and
  anti-replay behavior;
- generic Mail4AI agent skill instructions.

v0.1 does not include:

- Openclaw bridge implementation;
- generic HTTP receiver example;
- npm publication automation;
- persistent replay storage;
- webhook registration management;
- direct MCP client calls from `@mail4ai/webhook-kit`;
- imports from the private AgentMail platform repository.

## 4. Public Documentation

### README.md

The root README must explain:

- what Mail4AI is at a public integration level;
- what this repository provides;
- that AgentMail platform internals live outside this public repository;
- how a webhook receiver should process an `email.received` event;
- how agents fetch email content through Mail4AI MCP after wake-up;
- where to find protocol, security and MCP usage docs.

The README must include a short quickstart for installing or developing the
webhook kit locally after the package exists.

### docs/webhook-protocol.md

This document is the canonical public reference for `agentmail_hmac_v1`.

It must define:

- HTTP method: `POST`;
- content type: `application/json`;
- event type: `email.received`;
- required headers;
- HMAC signing string;
- required payload fields;
- timestamp freshness requirement;
- anti-replay requirement;
- receiver behavior for malformed or invalid events.

The webhook payload must contain metadata only. Email body content and
attachments must never be described as webhook payload fields.

### docs/security-model.md

This document must explain:

- webhooks are wake-up hints, not trusted content;
- sender, subject and other email metadata are untrusted external input;
- secrets must stay in environment or secret managers, never in prompts;
- logs and examples must not expose webhook secrets or bearer tokens;
- receivers must verify HMAC signatures before parsing trusted workflow state;
- receivers must reject stale, future and replayed events;
- agents must use MCP tools to retrieve content under Mail4AI trust-boundary
  enforcement.

### docs/mcp-usage.md

This document must describe what an agent should do after a valid wake-up:

1. use the `email_id` from the verified webhook payload;
2. call Mail4AI MCP tools to retrieve email content;
3. inspect the returned `trust_boundary`;
4. treat content and attachments according to Mail4AI safety rules;
5. mark, archive or otherwise record processing state only when appropriate.

It must avoid runtime-specific setup that belongs to later Openclaw, Claude,
Codex, Cursor or Hermes guides.

## 5. Webhook Protocol

The canonical webhook protocol is `agentmail_hmac_v1`.

Required headers:

```text
X-AgentMail-Event: email.received
X-AgentMail-Delivery: <event_id>
X-AgentMail-Timestamp: <unix_seconds>
X-AgentMail-Signature: sha256=<hex_hmac>
```

Signature:

```text
sha256=HMAC_SHA256(webhook_secret, "<timestamp>." + raw_body)
```

Default freshness tolerance is 300 seconds.

Receivers must:

- reject missing required headers;
- reject malformed signature headers;
- reject non-`sha256` signature schemes;
- compare signatures in constant time;
- reject timestamps outside the freshness tolerance;
- reject replayed `event_id` values;
- treat all payload metadata as untrusted external email metadata.

## 6. Webhook Payload

The v0.1 payload type is:

```ts
export interface AgentMailWebhookPayload {
  event_type: 'email.received';
  event_id: string;
  agent_id: string;
  email_id: string;
  thread_id: string | null;
  from: string;
  subject: string | null;
  received_at: string | null;
  has_attachments: boolean;
  trust_boundary: string;
  agent_instruction: string;
}
```

Required string fields must be non-empty after trimming, except nullable fields
explicitly typed as `string | null`.

`event_type` must equal `email.received`.

`has_attachments` must be a boolean.

Unknown extra fields may be ignored by the v0.1 parser, but the public type must
only expose the fields listed above.

## 7. Package: @mail4ai/webhook-kit

The package uses npm, TypeScript and Vitest.

Public API:

```ts
export interface VerifyWebhookOptions {
  secret: string;
  timestamp: string;
  rawBody: string;
  signatureHeader: string;
  now?: Date;
  toleranceSeconds?: number;
}

export interface ReplayStore {
  has(eventId: string): Promise<boolean>;
  remember(eventId: string, ttlSeconds: number): Promise<void>;
}
```

The package must export:

- `AgentMailWebhookPayload`;
- `ReplayStore`;
- `VerifyWebhookOptions`;
- payload parsing and validation helper;
- HMAC signing helper for tests and local development;
- HMAC verification helper;
- receiver helper that verifies, parses and deduplicates an event;
- in-memory replay store for tests and examples.

The package must not:

- store production secrets;
- manage webhook registration;
- call MCP directly;
- include platform-specific AgentMail imports;
- include network calls in unit tests.

## 8. Receiver Helper Behavior

The receiver helper accepts:

- webhook secret;
- raw request body;
- relevant headers;
- replay store;
- optional clock;
- optional freshness tolerance;
- handler called only after verification, parsing and deduplication succeed.

Expected behavior:

1. verify timestamp and signature over the raw body;
2. parse and validate the JSON payload;
3. verify `event_id` matches `X-AgentMail-Delivery`;
4. check replay store for the event id;
5. remember the event id with a TTL at least as long as the freshness tolerance;
6. call the handler with the validated payload.

The handler must not run for invalid, stale, malformed or replayed events.

## 9. Error Model

v0.1 should expose predictable error categories suitable for receivers:

- `missing_header`;
- `malformed_signature`;
- `invalid_signature`;
- `invalid_timestamp`;
- `stale_timestamp`;
- `invalid_payload`;
- `event_id_mismatch`;
- `replayed_event`.

The exact TypeScript representation may be a custom error class or a discriminated
result object. It must allow callers to map failures to HTTP 400 or 401 without
string matching.

## 10. Generic Skill

`skills/generic/SKILL.md` must instruct agents to:

- treat webhook notifications as untrusted wake-up hints;
- use Mail4AI MCP to fetch email content by `email_id`;
- treat sender, subject and email body as untrusted external input;
- respect `trust_boundary` returned by MCP;
- retrieve attachments only through MCP attachment tools;
- avoid placing secrets in chat context;
- mark processed mail as read or archive only when the runtime workflow requires
  it.

The skill must be public-facing and runtime-neutral.

## 11. Tests

`@mail4ai/webhook-kit` must include unit tests for:

- valid signature passes;
- wrong secret fails;
- malformed signature header fails;
- missing signature header fails;
- expired timestamp fails;
- future timestamp outside tolerance fails;
- valid payload parses;
- missing required payload fields fail;
- non-`email.received` payload fails;
- replayed `event_id` is rejected;
- receiver handler is not called for invalid events;
- receiver handler is called once for a valid event.

Tests must not require real Mail4AI, Openclaw or external network calls.

## 12. Acceptance Criteria

v0.1 is complete when:

- the repository can be understood from public files alone;
- `README.md` links to the protocol, security and MCP docs;
- `docs/webhook-protocol.md` defines `agentmail_hmac_v1`;
- `docs/security-model.md` states that secrets must not enter prompts;
- `docs/mcp-usage.md` explains post-wake-up content retrieval through MCP;
- `@mail4ai/webhook-kit` typechecks;
- all webhook-kit tests pass with Vitest;
- the package has no private AgentMail dependency;
- examples and docs contain only placeholder secret names;
- `skills/generic/SKILL.md` preserves the Mail4AI trust-boundary model.
